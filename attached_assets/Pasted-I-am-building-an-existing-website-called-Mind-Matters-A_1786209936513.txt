I am building an existing website called Mind Matters: A Student-Led Mental Wellness Program. The website is designed for students in a school setting and allows students to create age-appropriate wellness content that is reviewed by a teacher before it becomes public.

Please add a complete student contribution and teacher approval system to my existing website. Do not redesign or remove the public-facing website I already have unless necessary. Keep the current Mind Matters branding, navigation, layout, and overall visual style consistent.

MAIN GOAL

Students should NOT need access to my Replit code or Replit workspace.

Instead, students should log into the Mind Matters website and work through a private student dashboard.

Students should be able to:

See their assigned role/job
See their current team
View assigned projects
Create and edit drafts
Research and record sources
Submit work for peer review
Review another student's work when assigned
Submit finished work to the teacher
Leave handoff notes for future classes
Continue unfinished work from previous student groups

Nothing created by students should become publicly visible unless a teacher/admin explicitly approves and publishes it.

Create three permission levels:

Public visitors do not need editing permissions.

SAFETY REQUIREMENTS

Because this is a student mental wellness website, safety is extremely important.

Please create strong safeguards.

Students should NOT be able to publish:

Personal contact information
Private student information
Medical advice
Diagnoses
Dangerous instructions
Crisis-related instructions
Inappropriate language
Personal identifying information about another student

Include a reminder on student submission screens:

"Do not include private information about yourself or another student. Mind Matters provides general educational wellness information and does not replace help from a trusted adult or professional."

Flag submissions for teacher review if they contain potentially concerning or sensitive terms.

Flagging should NEVER automatically punish, discipline, diagnose, or message a student.

Instead, simply mark the submission:

Teacher Attention Recommended

so the teacher can review it privately.

All flagged content should remain private.

AUTHENTICATION

Use a secure authentication system appropriate for a school website.

Do not require students to become Replit project collaborators.

Keep authentication separate from Replit project editing access.

Build the system so different users receive different permissions based on their role.

If authentication requires a choice that may affect student privacy or school-policy compliance, stop and clearly tell me what needs to be selected rather than making a risky assumption.

PRIVACY AND SECURITY

Prioritize student privacy.

Use role-based access controls.

Students should only access data necessary for their work.

Teacher/admin routes must require teacher/admin authorization.

Do not rely only on hiding buttons in the interface.

Protect restricted information on the server/backend as well.

Public visitors must never be able to access private student drafts through a direct URL.

Do not expose database credentials or private keys in client-side code.

Use environment variables/secrets appropriately.
